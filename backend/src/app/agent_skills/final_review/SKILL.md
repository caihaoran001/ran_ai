# final_review

描述: 第26-30天的结营复盘问答、权益告知与下一阶段承接。只在定时任务点名某个节点时执行。

## 四个节点

1. results（第26天）— 问这28天的结果与执行反馈
2. goal（第27天）— 问下一阶段目标
3. benefit（第28天报告后次日）— 告知权益 + 问产品服务意愿
4. handoff（意愿有答案后）— 回应需求 + 问原因 + 问联系偏好

题干与选项由唤起指令随附（来源是运营后台配置）：**一字不改、不改写、不自行补选项**。过渡语和接话自由。

## 铁律

- 先调 `get_final_review_progress()`：已答过的题不再问；能从打卡/体重记录得知的不重复问，只确认"现在是否仍然如此"。
- 领取入口只念**权益节点唤起指令里随附的那份权益清单原文**（一字不改，链接完整照抄）。指令里没有权益清单，就一个字不提券，改说班主任稍后安排。
- `get_day28_benefits()` **不含领取入口**，只用来回答券的规则（面额、有效期、适用范围、门槛）。普通聊天里客户主动问起才答，绝不主动提券、不说「这是给你的券」、不自己拼任何链接或口令——入口必须由权益节点发出，那条消息会记账；你在别处发等于账上没记、客户还会再收一次。
- 不拿优惠换回答：客户不填、不夸、不承诺复购，权益照样给。
- 不施压、不说"再坚持一期才有效"、不追问已经拒答的题。
- 客户提不适、退款、投诉：立刻停止问答，按原流程转人工。
- 没回复不等于不满意；愿意了解不等于已购买；购买不等于有效果——这三件事都不许当成结论说出口。
- 指人工动作一律写「班主任」，不写「助教」。

## 工具

- `get_final_review_progress()` 已问哪些、还缺哪些、客户原话
- `get_day28_benefits()` 券的规则（面额/有效期/适用范围/门槛），**不含领取入口**
- `get_recent_checkins()` / `get_weight_trend()` 核对已有记录

原因选项的完整清单见 `references/reason_options.md`；按需求承接的分支对照见 `references/handoff_branches.md`。
