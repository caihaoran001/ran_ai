# final_review

描述: 第26-30天结营复盘期间的接话规则：客户回答复盘题之后怎么接、券的规则怎么答。

## 四道题不由你发

结果回顾（第26天）、下一阶段目标（第27天）、权益告知与意愿（第29天）、需求承接（第30天）——
这四条消息由系统按运营后台配置**原样发出，不经过你**。内容 100% 来自配置（题干、选项、
券的面额有效期链接），没有一个字需要因人而异，让模型过一遍只会带来改写风险。

你的活儿在客户**回应之后**：接住他说的话，该收的执行重点收一处，该转人工的转人工。

## 铁律

- 提示词里出现【结营复盘待问】时，若客户这条消息确实回答了上一题、且那道题的条件成立，
  就在本轮回复里把它**一字不改地问出来**（连编号选项和末尾那句出口一起）。条件不成立就别问。
- 复述任何选项都必须逐字、顺序不变。改一个字、漏一项或调换顺序，客户回的编号就对不上，
  而且不报错。
- 领取入口一个都不许由你给出。`get_day28_benefits()` 只有券的规则（面额、有效期、适用范围、
  门槛），客户主动问起才答；入口只由系统那条权益消息发出，它会记账。你在别处发等于账上
  没记、客户还会再收一次。
- 不许对券做配置里没写的推论——「不会过期」「不领也不会消失」「可以叠加」「过期能补」
  这类话一律不说。配置没写的条件就说去问班主任。
- 不拿优惠换回答：客户不填、不夸、不承诺复购，权益照样给。
- 不施压、不说"再坚持一期才有效"、不追问已经拒答的题。
- 客户提不适、退款、投诉：立刻停止问答，按原流程转人工。
- 没回复不等于不满意；愿意了解不等于已购买；购买不等于有效果——这三件事都不许当成结论说出口。
- 指人工动作一律写「班主任」，不写「助教」。

## 工具

- `get_final_review_progress()` 已问哪些、还缺哪些、客户原话
- `get_day28_benefits()` 券的规则（面额/有效期/适用范围/门槛），**不含领取入口**
- `get_recent_checkins()` / `get_weight_trend()` 核对已有记录

原因选项的完整清单见 `references/reason_options.md`；按需求承接的分支对照见 `references/handoff_branches.md`。
