# 交付文档内容优化建议（对照 V2.0，仅聚焦"生成的文档内容"）

## 立场（先说清楚）
客户这份 V2.0 是用 GPT 生成的设计稿，**GPT 并不了解我们系统的真实实现、已有结构和线上约束**。所以它只能当**灵感参考，不作为执行蓝本**——我们以现有系统为准，只挑"我们确实缺、且对用户有真实价值"的少数点吸收，**不照搬它的章节划分、不为对齐 V2.0 而改结构、不被它牵着走**。

本次**只谈一件事：两份交付文档的内容**(《个人能量重启处方单》+《28天执行标准与打卡要求》)。架构拆分、JSON 协议、风控分级、证据置信度等一律不在本次范围，避免摊大、避免反复变。

---

## 我们现在的文档结构（已自成体系，运行良好）

**处方单（14 节）**：1 用户信息概览表 / 2 一句话结论 / 3 为什么这样判断 / 4 现在的身体状态该关注什么(含胰岛素抵抗·瘦素·激素阶段判断) / 5 成功路径(不只28天) / 6 长期体质与失衡初判 / 7 模块诊断 / 8 预期变化 / 9 这28天最不能打折的一件事 / 10 本周直接执行 / 11 产品(早C午B晚A) / 12 特别提醒 / 13 前7天信号 / 14 说明(免责)。

**执行单**：减重带 / 总路径目标 / 28天目标 / 当前阶段目标 / 执行总原则 / 节律底盘 / 28天逐周执行标准(表) / 每日5项打卡 / 第5–12周说明 / 每周通过标准 / 提醒。

**结论：我们的结构已经覆盖了 V2.0 文档想要的绝大部分**(信息概览、一句话结论、判断依据、成功路径、模块诊断、产品意义、本周执行、预期变化、特别提醒、逐周执行、5项打卡、每周通过标准都有)。不存在"推倒重来"的必要。

---

## 对照 V2.0，真正值得吸收的——只有 3 点

### ① 处方单加一节「对您目标的直接回应」🟢建议做
- **缺口**：我们现在把"用户目标能不能达成"散在"一句话结论"和"判断"里，**没有一个正面、集中回应用户目标的段落**。用户最关心的就是"我想减10斤行不行"。
- **怎么做**：在处方单靠前加一节，固定逻辑：复述用户原话目标 → 认可动机 → 明确给结论(可行/可冲刺/当前不建议/需医疗评估) → 一句话依据 → 基础目标 + 挑战目标 + 冲刺条件。
- **价值**：用户体验最直接的提升点，成本中等(LLM 多产出一个结构化字段 + 模板加一节)。

### ② 执行单「调整与停止条件」强化 🟢建议做
- **缺口**：我们执行单结尾只有一句较弱的"提醒"，**没有清晰的"什么情况减半/前移/暂停/联系班主任/就医"**。
- **怎么做**：把结尾"提醒"扩成明确的停止与求助条件(尤其心慌/失眠/不适→暂停产品并联系班主任，红旗症状→就医)。
- **价值**：**安全相关**，和我们一直在做的去医疗化/安全把关同向，成本低。

### ③ 执行单目标做成「基础 / 挑战 / 长期」分层 🟡可做
- **缺口**：执行单现在只突出"28天目标"，**基础目标 vs 挑战目标 vs 长期目标的分层不够清晰**。
- **怎么做**：在"目标摘要"里把三档显式列出(基础目标=高确定性，挑战目标=达标条件下冲刺，长期=12周)。
- **价值**：管理预期、避免"承诺单一数字"，成本低(字段已有部分，强化展示)。

## 明确不采纳 / 不照搬
- ❌ **不为对齐 V2.0 的章节数/章节名改结构**。我们的14节已自成逻辑，V2.0 的"14节"只是它自己的排法，不是标准。
- ❌ **不把饮食规则、运动规则拆成独立章节**——我们融在"本周执行/逐周执行标准"里更紧凑，拆开反而碎。
- ❌ **不改文档名为"诊断报告/执行建议书"**——一来"诊断"二字与我们一直坚持的**去医疗化**相悖(我们刚在各处避免"诊断/处方"式医疗措辞)，二来这是命名问题、不是内容问题。要不要改名单独再议，不混进本次。
- ❌ V2.0 的"代谢节律评估""模块诊断"等——我们**已经有**(第4、7节)，不重复造。
