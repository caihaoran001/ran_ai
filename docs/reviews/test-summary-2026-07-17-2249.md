# Agent 回复停止规则复测总结

## 结论

本次针对真实回放暴露的两个问题完成修正：用户只是说日常安排时，不再主动输出饮食方案；影响判断的信息不足时，先追问一个关键点并停下。

相关 Mock 回归 86 项全部通过。用户授权的 3 次 `deepseek-v4-pro` 真实调用已全部执行，未追加重试，三个核心验收点全部达标。

## 通过项

- 自助餐社交闲聊：不再主动给进食顺序、饮品、运动或体重打卡建议。
- 杂粮米后饥饿：只追问这顿还吃了什么，没有用“可能”自行补全餐食并直接给方案。
- 吃甜后不适：先澄清是胃不适、心慌还是犯困，不直接做生理原因归因。
- 三条真实回复都在 1～2 句，保持了专业、克制的表达。
- 只替换了现有的 2 条规则和 2 个示例，规则数和示例数没有增加；没有新增模型链路或输出后置修改。

## 非阻断性观察

自助餐回放发生在接近 23:00，模型因而补了一句“店可能收摊”的时间判断。它没有再进行健康说教，但纯粹承接闲聊的稳定性仍有模型波动。该现象不影响本次两个核心问题的发布验收，也不建议为此继续叠加新规则。

## 发布建议

建议发布。当前结果同时满足：专业风格不变、普通回复收缩到 1～3 句、未求建议时不主动说教、关键信息不足时先追问，且没有增加生产 LLM 调用。
