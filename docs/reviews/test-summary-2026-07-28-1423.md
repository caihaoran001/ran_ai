# 真实模型三问卷抽样总结

测试时间：2026-07-28  
代码基线：`af54e3b`

## 结论

本次真实模型抽样不通过，当前版本不建议直接部署生产。

新方案的核心判断方向已经基本成立：

- 3份样本的管理带均符合预期：A带、D带、人工复核各1份；
- 3份近3个月趋势均与问卷直接答案一致；
- 3份都给出了2–3条问卷依据；
- D带没有机械承诺固定减重斤数；
- 用药样本能正确识别为“需人工复核”且不设置挑战目标。

但最终用户可见内容仍有4个必须先处理的问题：

1. 人工复核用户仍收到具体产品剂量，安全结论没有真正约束执行建议。
2. 五项个性化打卡有2/3被标题污染，真正的问题被截掉；其中人工复核样本丢失运动项。
3. 三份真实执行建议书全部为2页，没有达到“一页执行纸”。
4. 无明确数字目标的样本仍被生成“腰围缩减1–3cm”。

## 关键评价

### 管理带

通过。新A–D思想比旧固定斤数带更接近用户体感，也能正确使用人工复核出口。

### 身体趋势与证据

方向通过、证据质量部分通过。模型能引用用户问卷事实，但为了满足2–3条数量要求，会把当前体重、当前腰围、运动不足等横截面事实包装成趋势证据。更科学的表达应区分：

- 直接趋势证据：用户填写的近3个月体重变化；
- 当前状态支持信号：腰腹体感、睡眠、精力、食欲和运动。

不应把当前单点体重或腰围写成能独立证明上升/下降趋势。

### 五项个性化打卡

不通过。

- 样本2确实生成5项，顺序和类型基本正确。
- 样本1和样本3把“每日固定打卡/5项打卡”当成第1题，导致真正第5项被截掉。
- 样本2仍存在一个问题内包含两个判断条件的情况。

因此此前 Mock 测试证明的是“按标准格式返回时链路正确”，真实模型测试证明模型不一定严格遵守该格式，当前缺少可靠的生成后校验。

### 安全性

不通过。人工复核判断本身正确，但没有贯穿到产品排班和每日打卡。对于明确用药用户，在人工复核完成前仍给出半份/1份产品方案，属于发布阻断项。

### 格式与性能

- 真实执行建议书：3/3均为A4两页。
- 单次生成耗时：116–212秒。
- 三次总token：60,898。
- 配置口径费用估算：约0.27元。

生成均成功且没有截断，但真实延迟明显高于Mock测试，需要作为运营等待体验单独评估。

## 建议的最小修复顺序

1. 先修人工复核下游硬边界：人工复核时产品排班统一写“暂停给出具体剂量，待班主任/医生复核”，打卡不再要求产品完成。
2. 给每日打卡增加生成后结构校验：剔除“每日固定打卡/5项打卡”等标题，确认恰好5个有效问题且含运动项，否则重试或使用安全兜底。
3. 对基础/挑战/长期目标增加“数字必须能回溯到问卷原文”的校验。
4. 收紧执行建议书各字段最大长度或版式，使真实输出稳定为一页。
5. 把“趋势证据”拆成“1条直接趋势证据 + 1–2条当前状态支持信号”，避免伪造时间序列证据。
