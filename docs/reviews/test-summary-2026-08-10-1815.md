# RAG 评测体系实现验证总结

## 结论

本次最小版本已具备可用闭环：独立评测镜像按需运行并在结束后停止保留；后端只读报告接口可读取状态和逐条结果；前端能分别展示检索决策、改写伤害、RAGAS 四项和关键事实错误，并下钻原问题、改写、召回与回复证据。

本地零费用验证通过，但这只证明“评测系统能够正确运行和展示”，**不代表当前线上 RAG 质量已经达标**。

## 已验证能力

- 28 条版本化核心用例，其中 17 条负样本；正式首次生成时再只读抽取 25 条启用 FAQ，总计目标 53 条，负样本约 32%。
- 检索决策错误率与改写伤害率独立统计。
- RAGAS Context Recall、Context Precision、Faithfulness、Answer Relevancy 四项全部保留，不合并成总分。
- 数字、单位、否定和比较方向错误另计红色告警，不会被平均分抵消。
- 评测进程启用数据库只读会话和 SQL 写入拦截，并关闭消息渠道、网页搜索与有副作用工具。
- 前端桌面和移动端均可查看批次、指标、失败筛选和完整证据链。

## 未覆盖与发布判断

- 未在 ECS 构建评测镜像或创建评测容器。
- 未连接生产 RDS 验证 25 条 FAQ 的正式冻结数据集。
- 未获本次真实模型授权，因此未运行意图识别、真实召回、Agent 回复和 RAGAS 判官。
- 未运行全量后端 pytest 与完整 Playwright 基线，只运行本次改动相关定向测试。

建议：代码可以进入部署步骤；部署后先验证镜像、容器 `Exited` 状态、报告目录挂载和前端空态/Mock 报告。正式 53 条评测应在用户单独授权真实模型费用后执行，并如实记录首个基线，不为通过阈值调整数据或分数。
