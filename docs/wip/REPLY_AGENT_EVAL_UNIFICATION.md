# 回复 Agent 统一评测实施

> 2026-08-23，独立评测任务；按用户要求不占用 `CURRENT_TASK.md`。

## 【需求目标】

把现有 RAG 50 题与 Agent 30 道唯一题统一成一套回复 Agent 评测题库和执行入口。
最终固定 **80 道唯一题**，其中 **32 道应检索知识库**；其余题覆盖跳过检索、工具调用、
澄清、不回复、授权、转人工与常规表达。每题按适用条件开启指标，不对所有题强行运行同一组指标。

## 【为什么 / 约束】

- RAG 是回复 Agent 的条件能力，不应长期维护成独立顶层评测产品；
- 32 道检索题覆盖八类场景，每类至少四题：用量刻度、时间漏喝、产品搭配、冲泡规则、
  疑似不良反应、多轮指代纠正、上报夹带产品问题、召回缺失/干扰/冲突；
- 通用饮食、运动、睡眠和健康知识仍应跳过检索，不能为了凑数量改错生产口径；
- DeepEval 原生 Answer Relevancy 只诊断；Context Recall 0.80、Precision 0.70、Faithfulness 0.8333；
- 旧 RAG/Agent 报告继续可读；不删除历史报告；
- 本轮只编码与零费用测试，不部署、不调用真实 LLM、不发送消息、不修改业务数据。

## 【验收标准】

1. 单一版本化题库恰好 80 题，检索决策恰好 32 retrieve / 48 skip；
2. 每题固化 M0 基线，按条件附加 MR / MT / MB，字段引用和工具契约可校验；
3. 单一 Mock 入口跑完 80 题，0 模型调用、0 元，并生成统一报告；
4. retrieve、skip、工具、无回复、转人工至少各有完整路径测试；
5. 后台“回复质量”可识别并展示统一批次，旧批次兼容；
6. 相关 Python、TypeScript 与构建检查通过。
7. 批次总览单独展示查询改写损伤率，逐题可核对原问题/改写词、两侧召回分数与证据。
8. 已经逐题运行的观察项不得在总览丢失：回答正确完整度、原生答案相关性、
   Agent 任务完成/证据忠实/澄清/表达，以及高风险转人工成功率；观察项不改变整题门禁。
