# 燃人HumanBurning.AI 社群每日打卡模板

按健康管理优先级排序｜群内复制版

建议固定要求用户每天早上或晚上按以下格式打卡。

核心逻辑：先看结果，再看执行；先看节律，再看饮食；最后看体感和风险。

# 四、参数优先级说明｜给社群团队使用

| 优先级 | 参数        | 为什么重要                     |
| --- | --------- | ------------------------- |
| 1   | 晨起体重      | 用户最直观的结果指标，也是复购和售后判断的关键数据 |
| 2   | 腰围/肚围     | 比体重更能体现体型变化，尤其适合平台期用户     |
| 3   | 早C午B晚A完成度 | 判断用户是否真实执行产品节律            |
| 4   | 睡眠        | 影响食欲、代谢、第二天精神状态，是体重管理核心变量 |
| 5   | 饮食结构      | 决定结果上限，尤其是晚餐、夜宵、甜食、碳水     |
| 6   | 饮水        | 影响排便、代谢、体感和饱腹感            |
| 7   | 排便        | 前 3 天点火反应的重要信号            |
| 8   | 食欲/饥饿感    | 判断用户是否进入更稳定的饮食控制状态        |
| 9   | 运动/活动量    | 第 7 天后逐步加入，帮助突破平台期        |
| 10  | 身体体感      | 用于识别正反馈，如发热、水肿下降、精神变好     |
| 11  | 不适反馈      | 风险预警项，有异常必须优先处理           |
| 12  | 明日重点      | 把打卡转化为下一天行动，而不是单纯记录       |

# 五、建议最终采用方式

群内每天发简版。

第 1 天、第 3 天发标准版，用于建立用户基础状态和识别早期执行问题；第 7 天、第 14 天、第 21 天、第 28 天发阶段复盘版，用于总结周期变化、判断执行质量，并制定下一个 7 天目标。

这样既能降低用户打卡负担，又能保证 燃人HumanBurning.AI 后台沉淀足够完整的健康管理数据。
