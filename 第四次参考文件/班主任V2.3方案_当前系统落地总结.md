# 班主任 V2.3 方案：当前系统落地总结（修正版）

> 本文是给班主任 GPT 的“现状基线 + 落地清单”，不是重写班主任原文，也不是把当前系统改成另一套系统。
> 当前系统的运行契约、字段含义和安全边界优先；V2.3 只在此基础上补齐缺口。

## 一、先看结论

- 当前激活问卷已经有职业/家庭场景、既往减重和期待成果的原始答案；现在缺的不是重新加题，而是把答案接入 `intake_facts`、第二步输入、两份文件、H5 打卡和 Buddy。
- 入营仍是两次调用：第一步只做安全因子抽取，第二步一次生成 `shared_analysis`、画像和两份交付文件；不能拆成画像一次、两份文件各一次。
- 当前第二步的业务输出仍是 `shared_analysis`、画像、诊断报告、28 天执行建议书和 5 项 `daily_checkin`；V2.3 是在这些输出上增字段和消费方，不是另起一套输出。
- 后端负责事实整理、目标数字、路径状态和一致性校验；第二步模型负责把已给事实写成解释和文案，不能自行计算、改数字或补证据。
- C 类只有三个业务拍板点；其余成果集合、契约权重、产品上限和跨文件一致性都是必须执行的工程校验。

## 二、A 类：原始题目已有，待接入

不新增问卷，只接入已有答案：

- 既往减重经历；
- 职业身份、具体工作、责任方式、家庭角色；
- 工作时间规律、职业活动量、精力消耗来源、压力程度；
- 身体变好带来的价值、用户选中的 28 天期待成果。

其中营销来源题不属于 V2.3 交付链路，不接入职业/历史分析。

接入方式：

1. 后端从明确选项生成安全的结构化事实，并保留 `evidence`；没有直接证据就写 `unknown`。
2. 只建立针对这些非健康事实的白名单投影，不能把全部 `operator_only` 字段批量放行。
3. 健康情况、病史等自由文本仍只给第一步安全审阅；第二步只能接收第一步允许传递的结构化安全结论。
4. 禁止根据“程序员”“销售”等职位名称推断久坐、压力、自律或饮食行为。

## 三、B 类：派生字段和输出改造

### 1. 后端确定性整理

以下事实由后端整理，模型只能照抄或据此写文案：

- `time_control`、`schedule_predictability`、`occupational_activity`、`decision_load`、`social_eating_exposure`、`family_care_load`、`stress_load`：均带证据；无证据回退 `unknown`。这些四挡只服务于方案适配，不直接展示给用户，也不能没有消费方就强行新增。
- `candidate_action_windows`：根据问卷明确答案整理出的候选窗口；`confirmed_action_windows`：只有用户明确确认后才可填，不能把候选窗口冒充已确认窗口。
- 标准目标继续沿用当前权威字段 `28_day_auto_cap_kg`、`28_day_display_cap_jin`。班主任文档中的 `routine_28_day_cap_kg`、`routine_display_cap_jin` 如保留，只能做显式兼容映射，不能让两套同义字段分别成为权威。
- `path_basis`、`high_commitment_candidate`、`stretch_review_cap_kg/jin`、`execution_path`、`path_target_or_review_text`、`d7_execution_review_rule` 属于高承诺路径改造；在 C 类业务拍板前不新增运行逻辑，默认仍走当前标准路径。

### 2. 第二步模型生成、后端校验

第二步 schema 在现有结构上增加：

- `occupation_context`：职业/家庭场景、七类场景事实、已确认/候选窗口及证据；
- `weight_loss_history`：尝试过的方法、可核实的有效结果、难以维持/反弹信号，以及 `reusable_capabilities`、`do_not_repeat`、`history_questions_to_confirm`；
- `desired_outcomes`：严格保留问卷选中的 1–3 项，不丢项、不加项、不编造数字。每项必须有 `baseline_signal`、`tracking_method`、`day7_signal`、`day28_success_definition`、`priority_type` 五个子字段；用户选择集合由后端校验，模型只补充观察和表达方式，并选出一个与 `current_mainline` 一致的本阶段主追踪成果；
- `individual_cause_chains`：2–3 条“场景 → 重复行为/节律 → 身体或执行信号 → 目标阻碍”，每条带 `evidence` 和 `confidence`；只有单点相关时不能写成因果；
- `execution_contract`：3–5 个核心动作，权重合计 100，产品权重不超过 20；每项含完整版本、最低版本、事件锚点、替代方案和记录方式。完整版本记 1、最低版本记 0.5、未完成记 0；身体不适或明确暂停记 `protected_skip`。权重与必需字段由后端校验，模型负责把动作写清楚。

画像和两份文件还需承接：

- 画像：`occupation_fit`、`history_reuse`、`outcome_dashboard`、`execution_contract_summary`；
- 诊断报告：精简成因链和三项成果看板；
- 执行建议书：`core_action_contract`、`outcome_tracking`、路径目标和 D7 复评规则的短版，服从一页预算。

### 3. 必须保持的链路和权威关系

`intake_facts` → 第二步 schema → 后端归一化/校验 → 诊断报告与执行建议书模板 → H5 `daily_checkin` → Buddy 按需上下文。

- `shared_analysis` 是两份文件和 Buddy 共用的唯一业务来源；画像/文件不能各自重新判断。
- 保留两次模型调用和第一步安全隔离；新增字段不能绕过这两条边界。
- H5 仍严格 5 项：第 1 项产品、恰好 1 项 `activity`；第 2–5 项优先映射执行契约高权重动作和本阶段主追踪成果。
- Buddy 只有在上下文已注入时才能使用 `execution_path`、`execution_contract`、`desired_outcomes` 和 D7 规则；没有数据就不猜。

## 四、C 类：仅有三个业务拍板点

| 拍板点 | 当前系统 | V2.3 选项 | 未拍板前 |
| --- | --- | --- | --- |
| 活动频次 | planned 固定每周 3 次 | 允许 2、3、4 次 | 继续 3 次，不改代码 |
| 高承诺目标 | 标准上限为体重×5%、4kg、安全空间三者最小值 | 启用 `min（体重×7.5%、5kg、安全空间−1kg）` 业务复核线 | 只走标准目标，不展示高承诺数字 |
| D0/D7 状态机 | 当前没有高承诺确认和 D7 路径状态 | D0 明确同意每日记录且承诺 ≥85% 后进入；D7 按 ≥85%、70–84%、50–69%、<50% 处理 | 不新增事件、持久化和路径切换逻辑 |

说明：高承诺候选的五个条件（减脂在前 3 项、BMI/可靠体脂或腰围证据、安全空间与 1kg 缓冲、无安全/肌肉/恢复限制、至少 3 个可落地窗口）缺一不可；`high_commitment_candidate=true` 也不等于已经进入该路径。

## 五、D 类：必须保持并回归验证

- 文案顺序为“判断 → 证据 → 动作”；机制最多一句，禁止主动解释“首周水分/糖原不等于减脂”。
- 数字只能来自问卷或 `intake_facts`；不能编造腰围、结果或趋势。内部计算使用 kg/cm，用户目标展示使用斤，不能把“全系统一律斤”理解成内部单位也改成斤。
- 产品标准保持早 C/午 B/晚 A 各 1 标准份、300–330ml 水和相对时点（随餐、餐后 30 分钟内、晚餐后、睡前 1 小时）；高目标、高执行或体重停滞不得自动加量或增加 MCT。
- 执行建议书继续执行一页硬预算：`diet_rules` 每条 ≤34 字、`exercise_rules` 每条 ≤44 字；不删必需字段，不用重复解释填版面。
- 情绪稳定度和饭后困是两个独立候选打卡项；只有两项都被选入时才各占一个名额，不是强制各占一项。
- 必须校验：`desired_outcomes` 与问卷选择同集合；`execution_contract` 为 3–5 项且权重合计 100、产品 ≤20；管理带、BMI、基础/挑战目标、路径目标、阶段目标、运动频次在画像和两份文件中一致。

## 六、直接不采用

- 不把职位名称映射成久坐、压力、应酬或自律结论；没有证据就 `unknown`。
- 不新增 `career_context` 这类与当前系统不兼容的总字段，也不把班主任字段直接替换现有字段。
- 不把营销来源题接入 V2.3 职业/历史分析。
- 不把目标计算、路径切换或契约权重交给模型自由决定。
- 不因高目标、执行路径或体重停滞自动改变产品方案。
- 不改写班主任原文；只维护本总结，供班主任 GPT 据此提出兼容改造。

## 七、建议落地顺序

0. 先确认当前激活问卷原始字段已纳入接入范围（不新增题）。
1. 先拍板活动频次、高承诺目标、D0/D7 是否启用。
2. 接入安全结构化事实，补第二步 schema、后端归一化和必做校验。
3. 同步改画像、两份文件模板、H5 打卡映射和 Buddy 上下文；保持两次调用和安全隔离。
4. 最后再实现高承诺路径状态机，并用代表性样例回归验证字段不丢、目标不漂移、两份文件一致。
