# 班主任 V2.3 方案：当前系统落地总结

> 本文是对班主任两份 V2.3 文档的落地总结，不改写班主任原文，也不把当前系统改成另一套系统。
> 现有 ran_ai 的运行契约、字段和业务规则是基准；V2.3 只作为待落地的改造建议。

## 一、当前系统基线

- 入营保持两次模型调用：第一步只抽取安全因子；第二步一次生成 `shared_analysis`、画像和两份交付文件。
- 管理带、标准目标数字和安全下限由后端确定性计算，模型不能自行改写。
- 当前 planned 活动频次固定为每周 3 次；标准 28 天目标仍按“基线体重×5%、4 公斤、安全减重空间”取最小值。
- 当前问卷已有职业/工作、既往减重、期待成果等相关答案时，改造重点是传递和使用这些答案，不是重复新增题目。
- 当前第二步不会直接使用所有运营字段；健康情况自由文本仍只给第一步安全审阅。
- 当前群内 Buddy 没有自动拿到 `execution_contract`、`execution_path`、`desired_outcomes` 和 D7 规则。

## 二、如果完整落地 V2.3，需要新增

| 新增项 | 应落到哪里 | 说明 |
| --- | --- | --- |
| 职业/家庭场景事实 | `intake_facts`、第二步输入 | 使用问卷明确答案和证据；不能从职位名称推断。场景变量若要增加，只能作为内部变量，没证据为 `unknown`。 |
| 既往减重经验 | `intake_facts`、第二步输入和画像 | 增加尝试过的方法、有效元素、难以维持/反弹信号、可复用能力、禁止重演和待补问题。 |
| 三项健康成果 | 第二步输入、画像、诊断报告、执行建议书 | 保留用户选中的 1–3 项，不丢项、不加项；增加基线、追踪方式、D7 信号和 D28 成功定义。 |
| 个体成因链 | 第二步输出、诊断报告 | 新增 2–3 条“场景→行为→身体/执行信号→目标阻碍”，每条带证据和置信度；证据不足就少写。 |
| 执行契约 | `shared_analysis`、画像、执行建议书 | 新增 3–5 个核心动作，每项有完整版本、最低版本、事件锚点、替代方案、记录方式和权重。 |
| 群内执行上下文 | Buddy 运行时上下文 | 按需注入执行契约、主追踪成果、执行路径和 D7 规则；没有数据就不猜。 |
| H5 打卡关联 | 打卡生成和校验 | 仍保持 5 项结构，只让第 2–5 项优先对应高权重动作和主追踪成果。 |
| 一致性校验和回归测试 | 后端校验、模板、测试 | 校验执行契约 3–5 项、权重合计 100、产品权重不超过 20、成果集合与问卷一致、跨文件目标一致。 |

## 三、现有内容需要修改

1. **第二步输入**：把问卷中已有的职业、历史和成果答案整理成安全的结构化事实传给第二步；健康情况自由文本继续隔离。
2. **第二步 schema 和模板**：在当前结构上扩展新字段，不能直接用班主任文档的字段替换现有字段；旧字段和现有下载、存储流程要保持可用。
3. **文档呈现**：诊断报告增加精简成因链和成果看板，执行建议书增加执行契约短版；继续遵守一页版面预算。
4. **群内回复提示词**：保留现有工具权限、检索边界、实时数据规则和安全红线，只增加“有上下文才依据上下文”的执行/复盘行为。
5. **调用说明**：明确“两次调用”是两个阶段，失败重试是阶段内的容错，不拆成画像一次、两份文件各一次。

## 四、与当前系统冲突、需要拍板的事项

| 冲突 | 当前系统 | 班主任 V2.3 提议 | 兼容处理/待拍板 |
| --- | --- | --- | --- |
| 活动频次 | planned 固定每周 3 次 | 按场景输出 2、3 或 4 次 | 未拍板前保留 3 次；若采用 2/3/4，需另定判定表并同步后端、模板、打卡和测试。 |
| 高承诺目标 | 只有标准 5%/4 公斤上限 | 增加 7.5%/5 公斤复核线 | 不能只改提示词；需业务确认、目标展示规则和状态存储。确认前只保留标准路径。 |
| D0/D7 路径 | 当前没有高承诺确认和 D7 状态机 | D0 确认、D7 按完成度保留/降级 | 需要新增事件、持久化和原始文档版本规则；暂不做就从运行要求中标为“后续方案”。 |
| 职业四挡 | 当前没有对应变量和消费方 | `high / medium / low / unknown` | 只有当它真正驱动方案或统计时才新增；否则保留原始答案和证据，不做四挡。 |
| 过去一年趋势固定文案 | 不是所有问卷都有直接证据 | 有证据时插入固定判断 | 仅在问卷明确提供证据时出现；没有字段或证据就舍弃，不能套话。 |

## 五、直接不采用的内容

- 不做“程序员=久坐”等职位名称推断。
- 不引入我之前自行概括的 `career_context` 字段名；最终以当前系统确定的字段为准。
- 不因高目标、执行路径或体重停滞自动增加早 C/午 B/晚 A 剂量或 MCT。
- 不把班主任文档中的新字段当成当前系统已经支持的字段；没有对应代码位置时必须明确标为“需工程改造”。

## 六、落地顺序

1. 先确认活动频次、高承诺目标、D0/D7 是否采纳。
2. 在不改变上述业务规则的前提下，先做安全事实传递、新输出字段、模板、打卡和 Buddy 上下文。
3. 最后再做高承诺路径及其状态机；每一步都补跨字段一致性和回归测试。
